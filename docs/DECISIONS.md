# 결정 기록

2026-11-13에 사용자와 질문을 하나씩 주고받으며 정한 내용과 그 이유예요. 기능을 바꾸기 전에 여기서 이유를 먼저 확인하세요.

## 저장과 배포

| 결정 | 이유 |
| --- | --- |
| GitHub 새 공개 저장소 + GitHub Pages | 사용자가 GitHub 배포를 원했고, 무료 계정은 공개 저장소만 Pages를 쓸 수 있다. 기록이 공개되는 것은 사용자가 받아들였다. |
| 개인정보 자동 숨김 기능은 넣지 않음 | 사용자가 "처음부터 쓰지 않겠다"고 했고, AI도 쓰지 않기로 했다. |
| 보드에서 "보드 열쇠"(저장소 하나 전용 fine-grained 토큰)로 바로 저장 | 처음엔 GitHub 이슈 제출을 검토했지만 사용자가 "페이지 안에서 작업하면 바로 기록"을 원했다. 별도 서버(Cloudflare)는 계정을 늘리기 싫다고 해서 뺐다. |
| 열쇠는 sessionStorage, [잠그기]로 삭제 | 학교 공용 컴퓨터에서 쓰기 때문. 열쇠는 휴대폰 잠금 메모에 보관한다. |
| 휴대폰은 보기 전용 | 공용 PC 작업 + 열쇠 관리 부담을 줄이려고. 사용자가 선택. |
| 로컬 폴더 저장은 나중에 집에서 [폴더 연결] | 학교 공용 PC에 개인 폴더를 남기지 않으려고. |
| 매일 기록할 때 AI 토큰 0 | 사용자가 "토큰을 최소로, Codex에서도"를 원했다. AI는 처음 만들 때와 일요일 채점 때만 쓴다. |

## 매일 할 일

| 결정 | 이유 |
| --- | --- |
| 일일 항목: 아침 비타민 → 공고 확인 → 직무능력준비 → 운동 | 하루 흐름 순서. 공고판이 아침 9시에 갱신되므로 공고 확인은 오전. 영양제 2개는 비타민 하나로 합침(사용자 요청). |
| 직무능력준비 = CS 3개(고정) + 활동 1개(선택) | CS를 따로 떼면 직무 준비가 흩어지고, 한 칸에 "하나만 고르기"로 넣으면 CS를 건너뛰어도 완료가 된다. 둘 다 해야 완료로 정함. |
| 바쁜 날 모드 (CS 1개로 가볍게 완료, 주 2회) | 하루 1.5~2.5시간이 드는 구성이라 바쁜 날 포기하지 않도록. 횟수 제한으로 남용 방지. 잔디에는 연한 색. |
| 늦은 기록은 어제까지, 수정은 채점 전까지 | 너무 엄격하면 포기하고, 너무 느슨하면 기록을 믿을 수 없어서 중간으로. 채점 뒤 수정하면 비교가 의미 없어진다. |

## CS 연습

| 결정 | 이유 |
| --- | --- |
| 가상 게임 7개(요일별, 장르 모두 다름) | 실제 회사 이름을 쓰지 않으려고. 요일마다 다른 운영 현장을 경험하게. 장르는 실제 게임 목록과 맞춤. |
| 같은 요일엔 같은 문의가 매주 반복 | "같은 문의에 대한 답변"을 주차별로 비교해야 성장이 보인다(사용자 요청). |
| 세트는 한 달마다 교체, 3세트를 미리 만듦 | 한 달이면 같은 문의에 4~5번 답한다. 매달 AI로 만들면 토큰이 들어서 3개월 치를 한 번에. |
| 세 세트를 섞어 하루 = 기본 1 + 불만·항의 1 + 까다로운 상황 1 (2026-11-13 변경) | 사용자 요청. 한 달 내내 한 종류만 나오지 않고 매일 난이도가 섞이게. 달마다 조합을 돌려 3개월 동안 63개를 모두 쓴다. 대신 이벤트는 세 세트 것이 함께 보인다. |
| 이벤트·상황 정보·운영 정책을 함께 제공 | 근거 없이 쓰면 막연한 답변밖에 못 쓴다. 실제 CS도 정책을 보며 답한다. |
| 채점은 일요일 23:50 AI 코치(집 계정 예약 작업), 직접 체크 없앰 | 사용자 요청. 기준이 흔들리지 않고 피드백도 받을 수 있다. 매일 토큰 0은 유지. |
| 5항목 "있는지" 체크 + 정책 위반 −1 | 스스로도 이해할 수 있는 기준. 정책에 없는 약속은 실무에서 가장 위험한 실수. |
| ✍️ 내 글 / 🤖 AI 코치 구분, "다음엔 이렇게" 칸, 채점 기준 안내 | 회사가 볼 때 AI가 대신 쓴 게 아니라 코치로 썼다는 것이 보여야 한다. AI 활용은 숨기지 않는다. |

## 활동·미션·엑셀

| 결정 | 이유 |
| --- | --- |
| 활동 메뉴 4개: 패치노트 분석, 커뮤니티 보고서, 공지 작성, 엑셀·데이터 | 라이브 서비스 운영 실무를 연습 거리로 바꾼 것. |
| 메뉴 활동 = 연결된 미션 자동 +1 | 메뉴와 미션이 같은 활동이라 따로 기록하면 이중 작업. |
| 실제 게임 8개 장르별 상위, 매주 월요일 로테이션 | 주 단위여야 패치·커뮤니티 흐름을 볼 수 있고 주간 보고서 미션과 맞는다. 가고 싶은 회사 게임은 사용자가 나중에 추가. |
| 처음 미션: 커뮤니티 보고서 4주, 공지 5개, 패치노트 10개, 엑셀 대시보드 1개 | 사용자가 "직무 실력 쌓기"를 골랐다. 지원·접수 같은 일 미션은 원하지 않았다. |
| 엑셀 과제: 숨은 원인을 심은 가상 데이터, 숫자 문제는 즉시 채점(해시), 추론은 일요일 피드백 | 운영 업무의 "숫자 → 원인 추정 → 보고" 흐름 연습. 생성은 스크립트라 토큰 0. 컴활 공부와 연결. |

## 화면

| 결정 | 이유 |
| --- | --- |
| 탭: 오늘 · 미션 · 기록 · 통계 · 설정 · 사용법, 공유용 #summary | 회사 사람이 작업 화면이 아니라 요약을 먼저 보도록 공유 주소를 분리. |
| 기록 탭: 문의 카드 21개 → 주차별 답변(최근만 펼침) → 두 개 비교 | 사용자가 "비교 가능 + 어지럽지 않게"를 원했다. 비교는 두 개까지만. |
| 통계: 큰 숫자 3개 + 잔디 + CS 추이 위에, 작은 카드 3개는 핵심 숫자 보이게 | "자세히 보기"로 숨기면 지나친다는 사용자 지적. 회사는 꾸준함(잔디)과 성장(CS 추이)을 본다. |
| 대표 성장 사례 자동 선정은 하지 않음 | 사용자가 맞지 않다고 했다. |
| 사용법 탭: 실제 배치와 같은 점선 칸, 누르면 설명, 다시 누르면 닫힘 | 사용자 설계. 한 화면에 칸 6개 이하, 설명 3줄 이내로 깔끔하게. |
| 디자인: 모몽가 컬러 테마, 캐릭터·그라데이션 없음, 고운돋움 + Noto Sans KR | 사용자가 "전문적이면서 귀엽게", 캐릭터는 빼고 색만 따르기로 정함. |
| 이름 "취업 준비 챌린지보드" 유지 | 다른 이름(트레이닝 로그 등)을 제안했지만 사용자가 유지를 선택. |

## 공유·인수인계

| 결정 | 이유 |
| --- | --- |
| 설정 화면 + GitHub 템플릿 + 직무 팩 구조 | 다른 사람(다른 직무)도 쓸 수 있게. 오늘은 게임운영 팩만 만듦. |
| 안내 문서는 docs/ 한 폴더, 바깥엔 한 줄짜리 AGENTS.md·CLAUDE.md | 사용자 요청(한 폴더). 바깥 두 파일은 AI가 자동으로 읽는 위치라 표지판으로 남김. |
| 일요일 채점 예약은 집에서 쓰는 계정으로 | 학교에서 쓰는 계정과 다를 수 있어서. |
